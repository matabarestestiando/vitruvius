# API workflow

All `/api/*` routes and `/mcp/` use `Authorization: Bearer <owner token>`. Do not put credentials into URLs. Use JSON unless noted. `/healthz` is liveness; `/api/status` checks DB and configured dependencies. `/api/catalog` lists saved entities.

1. `POST /api/projects` with name/description; `POST /api/sessions` with project_id, board_id, title.
2. `POST /api/sessions/{id}/turns` with text/max_turns (1–12). Server-side history is shared by portal and MCP; concurrent requests on one session return 409. Read `/messages` to recover partial completed messages after a provider error.
3. `POST /api/contexts` with session_id/title/text. Optional scope REQUEST/SESSION/PROJECT/BOARD/EXPERT/GLOBAL, expert_ids, retention_hours (1–720) and permanent_consent. Default SESSION/24h. Permanent scopes require consent. Text is chunked immediately; `POST /contexts/{id}/index` builds vectors. Uploaded PDF/text/Markdown: request `/upload?content_type=...`, submit its presigned form directly to Spaces, then POST `/finalize` to enqueue extraction/embedding. List context in catalog, DELETE by ID, POST `/promote?scope=PROJECT` for explicit permanence. POST `/contexts/cleanup` runs expiry now.
4. `POST /api/experts` with name/specialty/principles/model/skill_ids; `POST /boards` with name/mission/expert_ids. `POST /skills` with name/content/previous_id/active appends a version. Multipart `/skills/import` takes name and file (.md or ZIP containing one SKILL.md); archive files are never extracted or executed.
5. `POST /api/sessions/{id}/draft` with kind requirement/adr/specification uses the discussion to save an unapproved draft. Manual `POST /artifacts` accepts project_id/session_id/kind/title/content/acceptance_criteria and optional previous_id. POST `/artifacts/{id}/approve` binds approval to that revision/hash. GET `/projects/{id}/export?target=codex|claude-code` refuses export while any current revision is unapproved.
6. Mount owner-selected repositories read-only under `/repositories`, then POST `/repositories` with project_id/path. GET `/repositories/{id}/inspect?query=...` returns matching lines or a listing; `file=...` returns one bounded safe file. Results include commit SHA. POST `/projects/{id}/review` with repository_id/query compares evidence to approved artifacts and saves a clearly scoped implementation review; it never claims to run tests.
7. Set server `MCP_ALLOWED_ORIGINS` and optional `MCP_SECRET_<NAME>` first. POST `/connections` with name/url/token_env/expert_ids/read_tools/write_tools, GET `/{id}/tools` to discover. POST `/{id}/call` with expert_id/tool/arguments invokes a read. A write first requires owner POST `/{id}/approve` with the same payload, then `/call?approval_id=...`. Approval is argument-bound and consumed before dispatch. Model tool calls can use allowed reads; write attempts create a pending exact-argument request visible in the portal. Owner POST `/tool-requests/{id}/execute` approves and dispatches it at most once.
8. POST `/api/memories` with scope personal/project/board/expert, target_id, text and approved=true. This is the explicit curation boundary; documents and full conversations are not automatically ingested. POST `/memories/search` with scope/target_id/query. A successful curation returns record_id for DELETE `/memories/{id}`, which removes its Graphiti episode and local pointer. Memory retrieval during discussion filters the same project, board, expert and personal namespaces.
9. DELETE `/api/sessions/{id}` removes temporary contexts, message history and graph checkpoints. Approved artifacts, permanent knowledge and explicitly approved memories have independent retention.

## MCP

Use Streamable HTTP `/mcp/`, owner Bearer authorization, and a compatible client. Implemented tools: list_boards, list_sessions, create_session, get_session, discuss, attach_context, get_skill export_development_prompt, create_project, list_contexts, create_context_upload, finalize_context_upload and propose_specification. Sessions are persisted by Vitruvius, so another authenticated compatible MCP client can resume by the same session ID. This is standard MCP tool distribution; no unverified native Skills-extension compatibility is claimed. Client-specific OAuth and connector setup require separate validation.

## Error handling

401 missing/invalid owner token; 403 scope or tool permission denied; 404 unknown entity; 409 concurrent session, missing exact approval, invalid upload state or unapproved handoff; 422 validation or consent failure; 502 provider failure; 503 unconfigured dependency. Error responses omit provider secrets and document bodies.
